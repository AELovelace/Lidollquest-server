GM Guide

Start with one NPC, one parcel, and one reward. You can build a bigger story once that small quest works.

Your first quest: the lost parcel

The player speaks to a guide, accepts a quest, finds a parcel, and returns for a reward. This example uses a quest token: a personal collectible that does not fill the normal inventory.

What you need: the NPCs, Quests, and Zones tabs. Use a hub you can visit easily. Keep the NPC stationary and leave timers and extra conditions off for this first try.

1. Create and publish the guide

Open NPCs → New NPC. In Basics, set Stable ID to parcel_guide, Name to Parcel Guide, and Wander radius to 0. Save and continue. Choose an existing walking sprite in Artwork.

In Dialogue, write: “I lost a parcel nearby. Ask me about quests if you would like to help.” Leave its destination at End conversation. Leave Quest links empty for now. In Review, preview the dialogue and click Publish.

2. Create the quest

Open Quests → New quest. Set Stable ID to lost_parcel and Name to The Lost Parcel. Write a short description. Keep Repeat policy at once and Time limit seconds at 0. Choose Return to NPC, select Parcel Guide as the Turn-in NPC, and tick Parcel Guide under Quest givers.

3. Set one collection objective

In Stages and objectives, keep the initial stage, name it “Find the parcel,” and write “Find the parcel near the guide, then return.” Click Add objective and enter:

Leave Zone restriction at Any zone for this example. Quest complete means the quest is ready to turn in; it does not immediately award anything.

4. Review and publish

The Placements step is a reminder of what to place; you will place it on the map next. In Rewards, try 5 XP and leave other rewards at zero. In Review, click Preview quest, simulate completion, close the preview, then Publish. Previews do not create player progress or pay rewards.

5. Place the guide and parcel

Open Zones and choose a hub. Select placement kind NPC, choose Parcel Guide, keep Persistent, and click a free map tile.

Switch the placement kind to Quest token. Enter lost_parcel_token in Objective target ID and “Lost parcel” in Display name. Choose an Object / token sprite or upload a PNG. Check the 32×32 preview, keep Persistent, and click another free tile near the guide.

The essential match: the collection objective's Target ID and the placed token's Objective target ID must both be lost_parcel_token. The quest ID and Objective ID are different labels and do not go in that placement field.

6. Play it once

  1. Enter that online hub with a test character. Stand beside the guide and press E.
  2. Choose Ask about quests in the conversation, select The Lost Parcel, review the offer, and choose Accept quest. The accepted quest now appears in the journal.
  3. Close the journal, stand beside the parcel, and press E. Check that the objective is complete.
  4. Return to the guide, press E, open the quest journal, and choose Turn in to NPC.
  5. Check the claim receipt. Claiming again must not award another reward.

This simple version requires collection and a return visit. To consume the parcel as a delivery, use the two-stage recipe in .

Optional polish: after publishing the quest, edit Parcel Guide's Quest links and tick The Lost Parcel, or add a dialogue choice with Quest action offer. Publish the NPC again. The Quest givers setting automatically adds the conversation offer above. You do not need to write an offer choice by hand. An authored offer choice for that quest takes the place of its automatic offer.

Names, IDs, drafts, and publishing

Players discover, accept, and resume quests by speaking to their NPC givers. The journal only lists quests already accepted; it cannot start or resume a quest. A Name is what players read. A Stable ID connects your content. Use lowercase letters, numbers, underscores, or hyphens, starting with a letter: parcel_guide, not “Parcel Guide”. Choose it before the first save; saved definition IDs are locked.

FieldWhat it identifies
NPC / quest Stable IDThe whole NPC or quest definition.
Stage IDA step inside one quest; another stage's destination can point here.
Objective IDA particular task inside a stage. Give each task its own ID.
Target IDWhat the task acts on: an NPC, monster, item, zone, or placed objective target.
Page ID / Branch IDA dialogue destination / a named quest outcome. These are different kinds of links.

Save draft keeps work on the server. Publish makes it available to online play. Publishing an NPC or monster does not place it; publishing a quest does not add its objects to the map.

Publish dependencies in this order: NPC first → quest second → NPC quest links or quest-action choices last. Ordinary NPC dialogue can be published before the quest exists.

Switching tools or opening this guide leaves editor forms in place. Save before closing the browser. Recover unsaved draft can recover the editor's session copy when available; it is not a substitute for saving.

Use to find IDs on this server. An item ID identifies the item; its sprite ID only identifies artwork.

If another DM saved first, the editor reports a revision conflict. Copy your unsaved text somewhere safe before choosing Reload server draft; then reapply your changes. Roll back and publish makes a previous published revision current again.

Retire / Restore changes the draft: publish it to apply that change. Retired quests stop new acceptance; accepted quests keep their original rules and rewards. Republishing will not update the quest already held by your test character. Abandoning and resuming also keeps that accepted version; use a fresh quest ID or another eligible test character to test a changed definition.

Which objective type should I use?

Give every objective a clear Player instructions sentence. Target IDs must match the actual content; names alone do not connect anything.

TypeTarget and player action
talkTarget: NPC ID. Speak to that NPC while this stage is active. For an existing resident, use its zone-qualified ID from Look up content IDs, not its display name.
visitTarget: a runtime zone ID, or a Location objective's target ID. Enter the zone, or step directly onto the placed location marker. Required count 1 is best for an arrival check.
interactTarget: an Interaction object's target ID. Stand beside it and press E.
collectWith Quest-bound token checked: target a Quest token placement and press E beside it. Otherwise: target an existing inventory item ID; the player must hold the required number.
deliverTarget: item or token ID. Set Delivery NPC ID and the token checkbox to match what is being delivered. Use Deliver in the online journal while speaking to that NPC. This consumes the requirements.
killTarget: a published monster ID. Defeat that monster in an online encounter. Publishing the monster alone does not make it spawn.
equipmentTarget: an existing item ID. Leave Equipment slot empty to accept any equipped slot, or enter a supported slot such as head. The character must wear it.
stateChoose State field, Comparison, and Required state value. Target ID is unused. For example, health with gte and 10 means at least 10 current health.
timerRequired count / timer seconds is the wait duration for this stage. Target ID is unused. This is different from the whole quest's time limit.

Zone restriction narrows event objectives to that zone; it does not create a destination or replace Target ID. Use a visit objective to require a location.

Normal inventory collection counts items currently held; it does not consume them. Equipment and state objectives must still hold when the other objectives in that stage finish.

Credit: Personal is the easiest starting point. Nearby party credit requires connected party members within eight tiles in the same map instance with the matching objective active. Combat credit uses eligible encounter participants. Each character must still accept and claim individually; shared delivery credit does not copy items into anyone's inventory.

Quest tokens and a two-stage delivery quest

A quest token is a private quest counter, not a tradable inventory item. A sprite only changes its appearance. Picking a potion icon does not make the token a usable potion.

For one parcel, use one token placement, count 1, and the same target ID everywhere. For three tokens, place three distinct tokens with that target ID; the same placement cannot be harvested repeatedly in one collection stage.

Stage A: collect the parcel

Set Stage ID to gather. Add a collect objective with Target ID lost_parcel_token, count 1, and Quest-bound token checked.

Stage B: hand it over

Add a stage with ID deliver_parcel. Add a deliver objective with the same Target ID, count 1, Quest-bound token checked, and Delivery NPC ID parcel_guide. Set this stage's Next stage to Quest complete.

Return to the gather stage and set its Next stage to the delivery stage before saving. Every stage must be reachable from the first stage; an unconnected new stage cannot be saved.

After collecting, the player speaks to the guide, opens the quest journal, and chooses Deliver lost_parcel_token. Delivery consumes the token and makes the quest ready. The player then turns in the quest for rewards.

Using real inventory items instead

Uncheck Quest-bound token in both objectives and use an existing item ID. Supply the item through an existing shop, drop, or reward. An Interaction object with that ID does not create an inventory item. A delivery removes the required items from the delivering character atomically.

Stages, choices, conditions, and timers

Stages run in order from the first stage. Choose Objectives required all when every task must finish, or any when one is enough. Each stage needs at least one objective.

Without branches, Next stage selects what happens when the stage finishes. Quest complete makes rewards ready to claim; Quest failed displays the failure message without rewards.

With branches, the player chooses an eligible branch after the objectives finish. Each branch needs a unique ID, a readable Choice label, and a Destination. Branch destinations replace that stage's ordinary Next stage. Example: “Return the parcel” goes to the delivery stage, while “Leave it behind” goes to Quest failed.

Connect every stage. Stages cannot loop back into a cycle. Use Repeat policy to make the whole quest replayable instead of linking its final stage to the start.

Conditions (all required) are extra checks, not scripts. gte means at least, lte means at most, and eq means exactly. Basics conditions restrict which NPC offers are available; objective conditions restrict credit; branch conditions restrict that choice. Leave them empty unless your story needs them. Make sure players can reach at least one branch.

Time limit seconds in Basics is a deadline for the whole quest; 0 disables it. A timer objective waits for its own count of seconds in its stage. With the online clock, time follows connected play and pauses after the presence lease expires or the server stops. With realtime, the deadline continues offline. Keep the deadline longer than any required wait.

Once means once per character. Daily and weekly use UTC periods; cooldown counts from a successful claim. Abandoning does not reset an attempt's timer or allow duplicate rewards.

NPC dialogue and quest offers

Create the NPC's Basics and Artwork first. Wander radius 0 keeps a quest giver easy to find. A positive radius allows bounded wandering around its placement.

In Dialogue, select a page on the left and edit its text. Continue to selects the next page when there are no choices. Add choice creates a player button with its own Go to page destination. End conversation is the end of that conversation, not quest completion.

Quest actionUse it for
noneOrdinary conversation navigation with no quest effect.
offerAccepting the selected quest. Publish the quest first and configure this NPC as an eligible giver. Rewards and forced equipment are disclosed before acceptance.
turn_inRequesting a reward claim for the selected quest. The player must be ready, and this must be its designated turn-in NPC unless journal claiming is enabled.
branchSelecting a named quest branch when that quest is waiting for a choice. Enter the branch's ID, not a dialogue page ID.

Quest links lists published quests associated with the NPC. In the quest's Basics, choose Quest givers and Turn-in NPC. Each giver automatically gets a paged Ask about quests menu for eligible quests that do not already have an authored offer choice. These choices preserve existing dialogue and services.

Preview page starts at the selected page; Preview conversation starts at the beginning. Both use your current text and never accept quests or grant rewards. Publish the NPC when finished.

Existing online residents can be selected in the quest's giver and turn-in lists. They keep their normal dialogue and services; the game adds an Ask about quests option. This editor does not create new shops or companion services.

Placing NPCs, tokens, objects, and locations

Open Zones, choose a hub or Dive, and wait for its live map. Select what to place, then click a free tile. The selector comes from the running server and includes Taiga and the other Dives.

  • NPC: select a published NPC definition. Its name and artwork come from that definition.
  • Quest token: enter an objective target ID, display name, and sprite. Use it with a collect objective with Quest-bound token checked.
  • Interaction object: enter a target ID, name, and sprite. Use it with an interact objective.
  • Location objective: enter a target ID and name. Use it with a visit objective; the player steps onto its marker.
  • Monster: select a published monster. See Monsters and live encounters for spawn behavior.

For tokens and objects, Object / token sprite offers shipped icons and managed artwork; Upload sprite PNG adds your own single-image artwork. The preview is 32×32. Choosing artwork does not change the objective target ID.

Persistent placements survive map replacement and relocate to reachable tiles if necessary. Current map only placements expire with that map. Use persistent for ordinary quests. If an expiring placement would strand active quests, replacement is blocked until you provide a persistent replacement or explicitly fail the affected quests.

Walls, entrances, fixtures, occupants, and their protected nearby tiles cannot be used. “The map changed” means refresh the map and choose again. Remove mode removes a clicked placement; required objectives report affected quests and require a replacement or explicit failure decision.

You do not need to regenerate terrain just to place quest content. Regenerate Dive replaces the whole Dive and resets its treasure and boss rewards after confirmation. Existing fights and defeat scenes must finish first; use the displayed blockers or cancel regeneration.

Rewards and consequences

Start small while testing. Each character accepts and claims their own quest. Repeated clicks, polling, or reconnecting do not pay a second claim.

  • XP: ordinary character experience.
  • Coins: LiDollCoins under the existing account-wide cap. The claim receipt shows the paid amount and any excluded excess; excess is not saved for a later day.
  • RPP: character roleplay points.
  • Items: choose existing items and quantities. Leave enough inventory space; a full inventory keeps the reward waiting.
  • Spell unlocks: choose existing spells.
  • Permanent stat changes: adjust only the supported fields shown. A negative value reduces that stat. Review these carefully, especially on repeatable quests.
  • Forced equipment / existing cursed items: equips the selected existing items with their existing effects. Explain those consequences in the quest description as well as reviewing the reward summary.

Return to NPC is the normal claim method. From journal allows claiming completed rewards without a return visit. It never allows accepting a quest from the journal: choose a Quest giver even when journal claiming is enabled. Finish battles, defeat acknowledgements, and pending inventory transactions before claiming.

Accepted quests pin their rewards. Changing the published reward later changes future acceptances, not players' current attempts.

Artwork and generation

NPC and monster Artwork steps support existing art, PNG uploads, and generation. Selecting existing art is the quickest way to test a quest. Map characters display at 32×32; portraits are separate artwork.

  1. Save the draft and describe the character in its Artwork step.
  2. Generate a design. This uses the saved server PixelLab key and provider credits, not player diamonds or private-sprite slots.
  3. Review the directional design. Approve it only when you want walking animation and portrait work to start.
  4. Wait for those stages; refresh generation progress or open Generation Jobs.
  5. Choose the portrait and explicitly assign the successful artwork to the draft. Review and publish separately.

Generation and assignment never publish by themselves. Partial failures keep successful stages. Read the job's failure message and retry only the failed stage; an uncertain paid submission needs review before another request. Cancellation keeps already completed artwork.

Tokens and interaction objects have their own sprite selector and single-image PNG upload in Zones. They do not need a generated enemy or NPC to supply an icon.

Loot: adjective + item + rarity

Every wearable or weapon a chest hands out is a unique copy. It rolls a rarity tier (common, uncommon, rare, epic, legendary), an item level from the route and floor, level-scaled base stats, and affixes: an adjective in front, an "of the ..." title behind from rare up, and bonus stat lines. The name tells the story at a glance: "Sodden Fluffy Diaper of the Nursery" in purple says epic, wet-themed and absorbent before anyone opens the tooltip. Common gear keeps its plain authored name and colour.

The Loot tab edits the live table. Edits reach the next chest on every route without a restart. Loot a player already holds keeps the roll it was given, and every Apply, Save, Retire and Reset is written to the audit log with the reason you type.

How one drop is decided

The roll is seeded from the chest itself, so regenerating a floor or previewing the same seed twice gives the same item. In order:

  • Base item. A numbered pool item (a "Latex Dress #7") is swapped for a generated base: a style (words only, "Maid") dressed onto a garment (the slot and every number, "Dress"). A diaper template only ever becomes a diaper garment. Quest items, consumables and locked items never roll.
  • Rarity tier. Each tier's weight is multiplied by the drop source's luck profile, then one tier is drawn. With the shipped weights (60 / 25 / 10 / 4 / 1) roughly one chest in a hundred is legendary before luck.
  • Item level. The route's base level plus per-floor growth for the floor, plus a small jitter (shipped: minus one to plus two), never above the item level cap.
  • Base stats. ATK, DEF and HP regen are multiplied by the level curve and the tier's stat budget. A zero stays zero: socks never gain ATK. Theme stats such as wet resist, bulk and childish only move through affixes.
  • Affix passes. The tier says how many affixes each slot gets (shipped: none, one, two, three, four). The first pick becomes the adjective; the next becomes the "of the ..." title from rare up. A dress counts as two slots, torso then pants, and takes its title from the pants pass. No two affixes on one item may share a tag, and if nothing legal remains for a prefix or title the roller falls back to a bonus line.
  • Legendary title. A legendary copy takes one line from the Legendary titles list and wears it in quotes in front of the whole name.
  • Coin value. The base value times the tier's value multiplier, growing with item level.
  • Curse or blessing. The curses and blessings roller runs last with the tier's bless and curse multipliers. Shipped: epics double their blessing chance, legendaries never curse and always bless.

Online, every chest and loose treasure pickup rolls with the chest profile. The mob, elite, boss and shop rows, and the drop and elite chances, describe the campaign's battle drops and shops; they ride along in the same table so both copies share one shape, but the desktop game reads the shipped file, so change those in the desktop editor and export.

Reading the tab, card by card

  • Rarity tiers. One row per tier. Weight is the raw draw chance, Affixes / slot how many lines each slot rolls (0 to 6), Suffix whether the tier may take an "of the ..." title, Stat budget x scales base stats (0.5 to 5), Value x scales coins, Bless x and Curse x feed the curses and blessings ramps (0 turns one off), Force blessing guarantees one, and Colour tints the name and chest.
  • Level curve and drops. level growth is the per-level stat multiplier (shipped 0.08, so level 100 gear is about nine times level 1); the preview under it shows a base DEF 2 item at levels 1 to 100 for every tier so you can see the shape before you apply. ilvl jitter min and max spread the item level around the route level. ilvl cap, level cap and stat cap are all 100 by decision. legendary cha gate is the charisma a shop needs before it will show a legendary. value level growth is coin growth per level. The enemy drop, boss drop, elite chance, elite HP, elite level bonus and boss level bonus fields are the campaign's battle-drop settings described above.
  • Luck profiles. One row per drop source; each cell multiplies that tier's weight. A zero removes the tier for that source, which is how shops never hand out epics. Common is never listed because it is whatever is left.
  • Over-cap bonuses. Base stats stop at 100 from level-ups, but gear may push the total past it. Per point % is what each point over the cap is worth, Ceiling % stops the bonus growing, and Effect names what the bonus does for that stat.
  • Route levels. Base is the item level on floor one and Per floor how much it climbs each floor deeper. The default row covers any route without its own row. A chest authored with its own level ignores this table.
  • Legendary titles. One per line. Keep at least one, or the panel refuses the retune.
  • Apply rates. Type why, then Apply. Every value is checked against its bounds and the whole card is refused if one is wrong, so nothing half-applies.

Writing an affix

Choose Write a new one, or select a row to edit it. Shipped affixes are retired rather than deleted so a later content push cannot resurrect a mistake by surprise; the Retired filter lists them and Restore brings one back. Custom affixes are deleted outright.

  • Id is permanent: 3 to 48 characters, a lowercase letter first, then letters, digits or underscores. Rolled loot remembers the id, so keep it once players hold the affix.
  • Adjective goes in front of the name ("Crinkly"); Title goes behind ("of the Nursery"). Give at least one, or tick Bonus-only for a silent stat line. An affix with both may be drawn as either.
  • Pick weight (0.1 to 1000) is relative to every other legal affix for that slot and tier.
  • Lowest tier hides the affix below that rarity. Set it to rare or above for anything you want to feel special.
  • Tags are comma separated. No two affixes sharing a tag can land on one item, so tag every wet-themed line "wet" and a diaper can never be both Sodden and Soaked.
  • Slots are the equipment slots it may roll onto. A dress asks torso and pants; the panel refuses "dress" as a slot for that reason. Pick at least one.
  • Stat lines, one to four. Each rolls a whole number between min and max, and both ends grow by the per-level value times (item level minus one). A line that rolls zero is skipped, and an affix whose every line can only roll zero is refused. Childish clamps to 0 to 10 and bulk never goes negative.
  • Flavour is a sentence appended to the item description once.

Never author is_diaper as a stat: the panel refuses it, because a diaper is identity, not a stat. Only the stats in the stat line dropdown may change.

Garments and styles

These are the generated base items. A garment owns the slot and every number: category, pick weight, the numbers (ATK, DEF, absorbency, bulk and so on), flags such as diaper, a coin value and a description where {style} and {style_lower} are substituted. A style is words only: a name, a description sentence, a pick weight, and the garments it may dress (or * for all of them). The panel refuses any number on a style. Retiring a garment is refused while a style still names it, and each category keeps at least one garment so a template always has something to become. Both editors follow the same retire, restore and delete rules as affixes.

Preview a roll

Pick a base item from the dive catalog, a source level, a luck profile and a seed, then Roll. The result is the exact item the server would hand out from the live table, with its tier, item level, affixes and stat lines spelled out. Roll another bumps the seed. Previews never touch chest receipts or the audit log, so roll as many as you like. Use the same seed before and after an edit to see exactly what changed.

Worked example: a wet-themed epic adjective for diapers

  • Write a new affix with id sodden, adjective "Sodden", weight 6, lowest tier epic, tag "wet", slots panties and diaper cover.
  • Add a stat line: wet resist min 4, max 8, per-level growth 0.1 on both ends, so a level 50 copy rolls roughly 8 to 12.
  • Flavour: "It has clearly been through a lot." Reason: "Epic wet adjective for the flood event." Save.
  • Preview a Thin Diaper at level 50 with the chest profile and roll until an epic appears. Confirm the adjective, then send a test character into any Dive: the next chest they open uses the new table.

Resetting

Reset rates returns only the rarity, curve, luck, over-cap, route level and title cards to the last content export. Reset garments and styles drops every custom or edited base. Reset everything does all of that plus the affix pool. Each asks for confirmation and is recorded in the audit log. Loot already rolled keeps what it was given in every case.

Shipped versus live

The desktop game editor's Loot tabs author the shipped baseline in the campaign data files; an export ships that baseline to the server and the offline game. The Loot tab here layers live overrides on top for online play only. Edited shipped entries show a Source of "edited", your own show "custom", and Reset returns to the export. Changes you want in the offline game, or in every future export, belong in the desktop editor.

Something is not rolling

  • My affix never appears. Check, in order: it is Enabled; the slot you are rolling is in its slot list; the tier you rolled is at or above its lowest tier; a tag on it is not already used by an earlier pick on the same item; its weight is not tiny beside the others; the tier rolls any affixes at all (common rolls none by decision).
  • Preview shows the plain name. The roll was common, or the base item is not wearable, or it is a quest, consumable or locked item. Roll another seed or raise the source level and luck.
  • A player's item did not change after my edit. Correct: loot keeps the roll it was given. Only new chests use the new table.
  • Apply rates was refused. One field is outside its bounds or the legendary title list is empty; the message names it. Nothing was saved.
  • A retire was refused. A style still names that garment, or it is the last garment in its category. Retire the style first, or write a replacement garment.

Monsters and live encounters

Use Monsters to create or duplicate a definition, edit combat stats and existing spells, select artwork, and author defeat scenes. Review then publish. Shipped defeat content is labelled Game default; editing combat stats does not require replacing its dialogue. Restore default removes a scene override.

Use Preview page for one starting page or Preview scene for dialogue followed by aftermath. First/repeat variants and branch destinations matter; previews never equip items or run consequences.

After publication, use Zones to place a monster manually or add it to a Dive's weighted spawn pool. A larger weight makes that monster more likely relative to the other pool entries. Monsters per room controls population; publishing spawn settings affects later spawns and protects active fights. Tick static and publish to freeze that map: the current floor is kept through weekly resets and only Regenerate map replaces it. Untick and publish to return the route to the weekly rotation.

Manual monsters are one-off by default; Respawn is optional. Hub monsters normally start battles through interaction. Roam and attack automatically opts into automatic engagement. A manually placed boss template does not automatically grant that Dive's boss-completion reward.

For a kill quest, use the monster's stable definition ID as the objective Target ID. The monster must actually exist in the player's online area and be defeated during the active stage.

Something is not working

The NPC is published but invisible
Publish creates a definition, not a placement. Place it in Zones, then check the player is in that exact online zone and map instance.
The quest is missing or cannot be accepted
New quests do not appear in the journal. Speak to the giver and choose Ask about quests. Check that it is published and not retired, the giver is correct, prerequisites and conditions are met, and repeat eligibility has not been used. A character can hold up to 16 active quests.
The token does not count
Accept first, activate the collection stage, tick Quest-bound token, and match the two Target IDs exactly. Stand beside the token and press E. One placement only supplies one token per collection stage.
I need three tokens but only get one
Place three distinct tokens with the same target ID. Increasing the objective count does not create more pickups.
Talking did not finish my objective
Speak again after accepting and while the talk stage is active. Check the NPC ID, including the zone prefix for an existing resident.
My visit marker does not count
Step onto it, rather than standing beside it and pressing E. Match the location target ID and any zone restriction.
The quest is ready but rewards are missing
Ready is not claimed. Speak to the designated turn-in NPC or use journal claiming if enabled. Clear inventory space and finish any battle or defeat acknowledgement. Check the receipt for the coin cap.
“Every stage must be reachable” or a cycle error
Connect the previous stage's Next stage to the newly added stage before saving. With branches, connect branch destinations instead. No stage may point back around a loop.
“Publish the referenced…”
Publish the NPC or monster first, then the quest. Add NPC choices that reference the quest afterward.
My edits do not change a player's quest
Accepted quests deliberately keep the version accepted. Test a fresh acceptance on another eligible character or with a new quest ID. Abandoning and then resuming through the NPC conversation does not refresh that version.
“This quest changed” in a conversation
Speak to the NPC again and review the current offer before choosing it.
“The map changed” or no reachable tile
Refresh the live map, then choose a tile away from terrain, entrances, fixtures, and occupants. Do not regenerate the Dive just to retry placement.
Generation finished but the old art remains
Assign the result to the draft, then publish it. Refresh the map/client; ongoing encounters keep the art they started with.
Lost work or conflicting edits
Try Recover unsaved draft for this browser session. Save copies of your text before reloading a conflicting server draft. Coordinate edits with the other DM.

When reporting a problem, include the zone, NPC/quest ID, active stage, and exact error text. Do not include account tokens or environment keys.

Before inviting players

  • All referenced NPCs, monsters, and quests are published; objectives and their placements use matching target IDs.
  • Each stage is connected, has objectives, and offers at least one reachable outcome.
  • The giver, delivery NPC, and turn-in NPC are clear in the instructions and reachable on the map.
  • Persistent placements are used for ongoing quests. Temporary event placements have an end-of-event plan.
  • Rewards, forced equipment, repeat policy, deadlines, and party credit are intentional.
  • Preview every dialogue choice and quest branch, then play accept → progress → deliver if needed → claim using a test character.
  • Reconnect mid-quest and confirm the same progress, conversation, and rewards. Test both success and failure paths.

The admin console edits live online overrides. The desktop game editor edits shipped offline source content; those changes require an export/release. They are separate workflows.

Before a server update, back up the live database safely and retain managed artwork, published history, jobs, and quest receipts. The deployment guide covers the database and data-directory backup procedure.
